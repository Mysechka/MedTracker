# Правила и указания для AI-агентов (MedTracker)

> Данный файл содержит обязательные архитектурные, интерфейсные и инженерные правила для всех AI-агентов, работающих с кодовой базой MedTracker. Нарушение этих правил строго запрещено.

---

## 🚫 1. КРИТИЧЕСКОЕ ПРАВИЛО НАВИГАЦИИ И UI: ОТСУТСТВИЕ ОТДЕЛЬНОЙ КНОПКИ «КУРСЫ»

### ⚠️ СТРОГИЙ ЗАПРЕТ:
- **Никогда и ни при каких обстоятельствах не добавлять отдельную кнопку/вкладку «Курсы» (Courses) в навигацию приложения!**
- Запрещено добавлять `SideNavItem Label="Курсы"` в боковое меню (macOS/Desktop).
- Запрещено добавлять `BottomNavItem Label="Курсы"` в нижнюю навигационную панель (Android/Mobile).
- Не создавать отдельные экраны навигации верхнего уровня для курсов (`CoursesView`, `CoursesNavigationItem` и т.д.).

### ✅ Как устроена работа с курсами:
- Курсы приёма лекарств **нативно встроены в карточки лекарств** и модальные окна создания/редактирования медикамента (`MedicationsView`, `AddMedicationDialog`).
- Пользователь настраивает курс (длительность, интервалы, частоту) непосредственно внутри карточки самого лекарства.
- В приложении существует **строго 4 основных раздела навигации**:
  1. **«Сегодня»** (`Today`) — текущий статус приёмов на день с быстрыми отметками.
  2. **«Лекарства»** (`Medications`) — каталог медикаментов с их курсами, дозировками и остатками.
  3. **«Медкарта»** (`MedicalCard`) — анализы, документы и медицинские файлы.
  4. **«Настройки»** (`Settings`) — профиль, часовой пояс, синхронизация и диагностика.

## 📱 2. Адаптивность и мобильный интерфейс (Android)

- **Отступы от системных жестов**:
  - На экранах с нижней навигацией (`MainView.axaml`) обязательно учитывать системную полоску жестов Android (home gesture pill).
  - У `Border` нижней панели навигации отступ снизу должен быть не менее `18-20px` (`Padding="4,6,4,18"`), чтобы системный жест не перекрывал подписи кнопок.
- **Предотвращение обрезания текста**:
  - Все текстовые блоки с описаниями, подсказками и заголовками должны иметь `TextWrapping="Wrap"`.
  - Запрещено допускать горизонтальное переполнение кнопок и пикеров на узких экранах (использовать `WrapPanel` вместо `StackPanel Orientation="Horizontal"`, где количество элементов может не поместиться).
- **Android Runtime**:
  - В классе `MedAndroidApplication.cs` всегда должен явно присутствовать метод `public override void OnCreate() { base.OnCreate(); }` во избежание сбоя `UnsatisfiedLinkError: n_onCreate`.

## 🏛 3. Архитектура проекта (Clean Architecture)

Проект строго следует принципам чистой архитектуры:
- `Med.Domain` — чистый C# без каких-либо внешних библиотек и фреймворков. Содержит только доменные сущности, value objects и доменные правила.
- `Med.Application` — контракты интерфейсов, Use Cases, DTO.
- `Med.Infrastructure` — реализация работы с БД (SQLite), Supabase, файлами, локальными уведомлениями.
- `Med.Presentation` — ViewModels на базе CommunityToolkit.Mvvm, навигация, сервисы UI.
- `Med.Ui` / `Med.Desktop` / `Med.Android` — XAML разметка (Avalonia UI) и платформенно-зависимый код.

**Правило зависимостей**: Зависимости направлены только внутрь к `Med.Domain`. Никогда не импортировать UI или инфраструктурные пакеты в `Domain` или `Application`.
